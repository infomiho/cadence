Main flow · Screen 03

Keep results fresh quietly

Eligible familiar-music metadata refreshes while the search stays open.

What to notice

  1. 1The query stays in the toolbar while the refresh runs.
  2. 2Refreshing is deliberately not a new control or section in the Search page.
  3. 3Only eligible, already-known metadata can make the quick preview faster.
Freshness improves early results without changing the visible search model.

Main flow · Screen 04

Complete without a reshuffle

The catalog response completes for a forgiving local match.

What to notice

  1. 1The original query remains visible; Cadence does not silently rewrite it.
  2. 2The first visible quick preview holds its position while new rows are appended.
  3. 3Every row is a Spotify result; local metadata only made the first answer available sooner.
Patching results into one stable list avoids the visual jump of replacing one source with another.

Alternate path · Screen 05

First launch stays usable

Branch: the library is still loading for a new account.

What to notice

  1. 1Search stays active during the initial import.
  2. 2Partial coverage is explicitly identified; it is not a definitive empty result.
  3. 3Catalog search can answer before the local collection is complete.
  4. 4Progress is nonblocking; counts are illustrative fixtures.
A new user should not have to wait for a whole library before trying search.

Alternate path · Screen 06

Cadence blocks the workspace when Spotify is not connected

Branch: the saved Spotify session is unavailable.

What to notice

  1. 1This follows Cadence’s existing signed-out scrim behavior.
  2. 2Local metadata is not presented as an offline-search or offline-playback mode.
  3. 3Signing in is required before Cadence exposes the workspace again.
A local search cache must not imply that Spotify playback works without a connection.
